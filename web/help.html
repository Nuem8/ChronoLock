How ChronoLock works

ChronoLock encrypts your secret in this browser and gives you a link. The server stores only the locked secret until it is opened or it expires. ChronoLock cannot read the secret. There is no account and no telemetry.

  • Payload limit: up to 32KB per secret.
  • Lifetimes: 5 minutes, 1 hour, 1 day, or 7 days.
  • Secure page: open ChronoLock over HTTPS, or on localhost. The browser will not encrypt a secret on an insecure page.

Sending a secret

  1. Enter the secret or config, or select Load file. Choose its lifetime, and choose whether to Delete after one reveal.
  2. Choose how to lock it, then select Create link.
  3. Send the link to the recipient.

Suitable for passwords, API keys, recovery codes, and small .env or configuration blocks.

Key in the link

Leave User key pair off. The decryption key is the part of the link after #.

  • The browser does not send the part after # to ChronoLock.
  • Anyone with the complete link can open the secret. Copy and send the whole link.

Lock to a public key

Turn User key pair on and paste the recipient's public key.

  • The link contains no decryption key. Only the matching private key can open the secret. ChronoLock never receives the private key.
  • If this browser already holds a key, User key pair starts on and the box is filled with that public key. Replace it with the recipient's public key, or turn User key pair off to put the key in the link.
  • View keys opens the key page, where you can reveal, download, copy, or delete the key in this browser.

Managing your keys

Open Your key to create a key, look at it, or hold one you already have.

Generate a new key pair

  • Generate new key pair creates a public key you can share and a private key that stays with you.
  • Nothing is saved in this browser until you store the private key, check I have saved my private key, and select Confirm and continue. Back leaves without storing it.

Key actions

  • Reveal private key: shows the private key on the page.
  • Download private key: saves chronolock-private-key.txt.
  • Delete local keys: asks a second time, then removes the key from this browser.

Import an existing key

Select Import an existing key and paste a private key. ChronoLock derives the matching public key. The two values have to be different.

If you lose the private key, a secret locked to its public key cannot be opened. ChronoLock cannot recover it.

Opening a secret

Open the link and select Reveal secret. Decryption happens in this browser. Save file downloads the opened text to this computer. When the secret was loaded from a file, the download uses that file name. ChronoLock does not receive the file or its name.

  • Key in the link: the part after # has to still be there. A link copied without it cannot be opened.
  • Locked to a key: if this browser holds the matching private key, Reveal secret uses it. You do not have to open User key pair.

Use a different private key

Open User key pair on the reveal page:

  • Load key fills the box with the key saved in this browser.
  • Load key file reads an unencrypted PEM private key (BEGIN PRIVATE KEY or BEGIN EC PRIVATE KEY) or a ChronoLock private-key file. A public-key file is refused. A PEM that still has a passphrase is refused. The file is used for this open and is not saved in the browser.
  • Clear removes the key from the box.

A wrong key, and expiry

  • A wrong private key does not open the secret and does not delete it.
  • With Delete after one reveal on, the secret is deleted only after the right key opens it. It also dies when its lifetime ends.
